# Yggdrasil 多轴仿真计算引擎 — 第一阶段开发计划

**文档编号**：`Phase1_DevPlan_20260601_v0.a.md`  
**状态**：初稿  
**作者**：Duke / Kiro  
**日期**：2026-06-01  

---

## 1. 阶段目标

基于 `mydesign/` 中的 DualGrid 双轨平行网格架构设计，完成 **3轴切削仿真计算内核** 的最小可验证原型（MVP），实现从"输入工艺参数 → 建立毛坯 → 生成刀具扫掠体 → 执行布尔切削 → 输出结果"的完整单步计算流水线。

**不包含**：渲染管线、状态机回滚、RCU 内存紧凑化、5轴逆向轨迹。这些属于后续阶段。

---

## 2. 需求分解与依赖关系

```
R1: DualGrid + VoxelSize 初始设定算法
 │
 ▼
R2: 用 DualGrid 方法建立初始毛坯计算模型
 │
 ▼
R3: 建立刀具固定轴线位移扫描体 SDF
 │  （与 R2 可并行开发，但集成测试依赖 R2）
 ▼
R4: 实现刀具扫掠体 SDF 与毛坯计算模型的切削计算
     （依赖 R2 + R3）
```

| 需求 | 前置依赖 | 核心输出 |
|------|----------|----------|
| R1 | 无 | `ResolutionSolver` 类：输入工艺参数，输出 D_v、d_v、N、降级标志 |
| R2 | R1 | `BilletBuilder` 类：构建宏观 FloatGrid SDF + 微观 PointDataGrid 边界 |
| R3 | 无（接口依赖 R1 的 D_v） | `ToolSweepSDF` 类：给定刀具参数+起止点，输出解析 SDF 评估函数 |
| R4 | R2, R3 | `CuttingEngine` 类：执行宏观过滤 + 微观掩码剔除 |

## 3. 技术约束与设计原则

### 3.1 平台兼容
- **主开发平台**：Mac mini M4 (2024), macOS, Apple Clang
- **目标兼容**：Windows ThinkPad X1, MSVC 2022
- **构建系统**：CMake 3.20+，独立子项目，不侵入 OpenVDB 主仓库构建

### 3.2 依赖
- OpenVDB 12.x（本仓库源码）
- Intel TBB（通过 OpenVDB 传递依赖）
- Blosc（压缩，可选）
- Google Test（单元测试）

### 3.3 设计原则
1. **敏捷迭代**：先求功能正确（低性能版），后续迭代追求 SIMD/AVX 优化
2. **单元测试驱动**：每个需求必须有对应的 GTest 用例验证数值正确性
3. **解耦设计**：R1~R4 各自独立编译单元，通过接口类组合
4. **数值安全**：所有浮点比较使用 epsilon 容差；坐标计算使用 double 精度

## 4. 里程碑计划

| 里程碑 | 内容 | 验收标准 |
|--------|------|----------|
| **M1** | R1 完成 | 给定典型工艺参数（t=0.01mm, R_min=5mm, F_min=1mm, L_max=500mm），输出正确的 D_v 和降级判定；GTest 通过 |
| **M2** | R2 完成 | 给定长方体毛坯尺寸，生成 FloatGrid（窄带 SDF）+ PointDataGrid（表面点云）；可序列化为 .vdb 文件并用 vdb_view 可视化验证 |
| **M3** | R3 完成 | 给定球头刀(R=5mm)从 A 点到 B 点的直线运动，生成胶囊体 SDF；对空间采样点返回正确的有符号距离值；GTest 通过 |
| **M4** | R4 完成（阶段交付） | 对 M2 毛坯执行 M3 的单刀切削，宏观 SDF 正确更新，微观点云掩码正确翻转；切削前后体积差与理论扫掠体体积误差 < 5%；可输出 .vdb 可视化 |

## 6. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| OpenVDB PointDataGrid API 学习曲线陡峭 | R2/R4 延期 | R2 先用纯 FloatGrid 实现单轨版本验证逻辑，再升级双轨 |
| Mac M4 (ARM) 与 x86 SIMD 指令不兼容 | 性能代码不可移植 | 第一阶段不写 intrinsics，使用标准 C++ 数学；SIMD 留到阶段2 |
| 微观点云密度计算复杂 | R2 水密性不足 | 第一阶段采用固定密度（每体素面 1 点），精加工自适应密度留后续 |
| 切削体积误差超标 | M4 验收失败 | 提高宏观网格分辨率（牺牲性能换精度），确认算法正确后再优化 |

---

## 7. 潜在风险点（强制质疑）

**【不同见解】**：当前方案将 R2 的微观轨（PointDataGrid）纳入第一阶段 MVP。但从敏捷角度看，第一阶段的核心验证目标是"切削逻辑正确性"，而非"微观精度"。建议考虑：

- **备选方案**：第一阶段仅实现宏观单轨（FloatGrid SDF 布尔差集），用 `tools::csgDifferenceSDF` 直接验证切削逻辑。微观 PointDataGrid 掩码剔除作为 M4 的"增强目标"而非"必达目标"。
- **理由**：降低首次集成复杂度，快速获得端到端可视化反馈，再逐步引入微观轨。
- **风险**：如果一开始就跳过微观轨，后续集成时可能发现架构假设不成立。

建议在 M2 阶段同时实现两个版本（单轨快速版 + 双轨完整版），以对冲风险。
