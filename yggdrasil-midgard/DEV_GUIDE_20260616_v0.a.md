## 1. 项目背景

### 1.1 项目定位

| 项目 | 路径 | 性质 |
|------|------|------|
| OpenVDB (主仓库) | `openvdb/` | 基础设施，提供编译后的库 (`install/`) |
| yggdrasil | `openvdb/yggdrasil/` | **原型项目**（测试/验证算法可行性） |
| **yggdrasil-midgard** | `openvdb/yggdrasil-midgard/` | **产品项目**（本项目，工程化实现） |

### 1.2 核心目标

三轴CNC铣削加工仿真引擎（未来扩展五轴），基于 DualTrack 架构：
- **MacroGrid** (FloatGrid)：宏观隐式场，大体素快速拓扑操作
- **MicroGrid** (PointDataGrid)：微观离散场，相对坐标存储高精度点法式数据

### 1.3 主设计文件

- `initialdesign0_0.a.md` — **唯一主设计大纲**，定义算法目标与五阶段管线
- 其余 `设计参考*.md` 仅为辅助资料

### 1.4 参考资源路径

| 用途 | 路径 |
|------|------|
| 原型代码参考 | `openvdb/yggdrasil/core/`, `yggdrasil/types/`, `yggdrasil/tests/` |
| 原型CMake参考 | `openvdb/yggdrasil/CMakeLists.txt` |
| OpenVDB安装 | `openvdb/install/` (include/lib/bin) |
| 设计文档归档 | `openvdb/mydesign/`, `openvdb/doc/` |
| OpenVDB源码参考 | `openvdb/openvdb/openvdb/` |

## 3. 编码规范

### 3.1 语言与标准

- C++17，与原型保持一致
- 编译器：Clang (macOS), MSVC (Windows)
- 构建系统：CMake >= 3.20

### 3.2 命名约定（沿用原型风格）

| 类别 | 风格 | 示例 |
|------|------|------|
| 命名空间 | 小写短名 | `midgard` |
| 类/结构体 | PascalCase | `MacroCut`, `ToolSweptSDF` |
| 成员函数 | camelCase | `evalSDF()`, `getBoundingBox()` |
| 成员变量 | m前缀 + PascalCase | `mVoxelSize`, `mToolType` |
| 局部变量 | camelCase | `leafNode`, `dirtyVoxels` |
| 常量/枚举值 | UPPER_SNAKE | `SAFE_MARGIN_U`, `BALL_END` |
| 文件名 | PascalCase | `MacroCut.h`, `ToolSweptSDF.cpp` |

### 3.3 代码组织

- 头文件使用 `#pragma once`
- 所有公共API在 `midgard` 命名空间下
- 头文件只放声明，实现放 `.cpp`（内联小函数例外）
- 优先组合而非继承；数据结构尽量POD-like

### 3.4 依赖管理

| 依赖 | 来源 | 版本锁定 |
|------|------|----------|
| OpenVDB | 本地 `install/` | 与仓库同步 |
| TBB | OpenVDB传递依赖 | 同上 |
| GoogleTest | FetchContent | v1.15.2 |

禁止引入未经讨论的第三方库。

### 3.5 精度与鲁棒性

- 几何计算一律使用 `double`（不用float做中间运算）
- 容差比较使用显式 epsilon 参数，禁止硬编码魔数
- SDF求值必须提供解析梯度，禁止6点有限差分（性能要求）
- 浮点相等判断统一使用容差函数

## 4. 构建与测试

### 4.1 构建命令

```bash
# macOS (Mac mini M4)
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build . -j$(sysctl -n hw.ncpu)

# Windows (ThinkPad X1)
mkdir build && cd build
cmake .. -G "Visual Studio 17 2022" -A x64
cmake --build . --config Release
```

### 4.2 测试策略

- 每个模块必须有对应的 `test_<module>.cpp`
- 精度测试：验证 Hausdorff 距离 ≤ ε
- 性能基准：关键路径提供 benchmark（参考原型 `bench_strategies.cpp`）
- CI 暂缓，本地验证为主

### 4.3 TDD 要求

**重要算法实现必须采用 TDD（测试驱动开发）**，流程如下：

1. **Red** — 先编写失败的测试用例，明确定义预期行为与验收条件
2. **Green** — 编写最小实现使测试通过
3. **Refactor** — 在测试保护下重构，确保不引入回归

**适用范围**：
- ToolSweptSDF 求值与梯度计算
- MacroCut CSG差集运算
- MicroCut 四叉树自适应细分与采样
- 边界重投影算法
- 内存规整与无锁注射
- 任何涉及几何精度保证的计算路径

**豁免条件**（以下情况可不强制TDD）：
- 纯数据搬运/格式转换（无计算逻辑）
- 日志/调试输出代码
- 直接调用OpenVDB现有API的薄封装

**TDD测试设计原则**：
- 测试用例必须覆盖边界条件（退化几何、零长度路径、刀具与工件不接触）
- 精度类测试必须有明确的数值容差断言
- 优先使用解析可验证的几何case（球体切平面、平面切平面等）

## 5. 运行时调试系统 (RtDebugSys)

项目集成 `RtDebugSys` 作为统一的运行时诊断工具。源码位于 `RtDebugSys_Standalone/`。

### 5.1 核心特性

- **零开销**：关闭时通过分支预测优化，对算法性能几乎无影响
- **热重载**：运行时修改 `RTDebug.cfg` 即可启用/禁用标签，无需重编译
- **异步日志**：后台线程写入，不阻塞 TBB 并行计算
- **标签自愈**：代码中新增标签自动追加到配置文件（默认禁用）

### 5.2 使用规范

**初始化**（main 入口）：
```cpp
RtDebugSys::Debugger::GetInstance().SetWorkspace("./debug_output");
RtDebugSys::Debugger::GetInstance().Activate(1); // 1=Normal, 2=Verbose
```

**标签命名约定**：`Phase{N}_{模块}_{关注点}`

| 标签 | 用途 | 级别 |
|------|------|------|
| `Phase0_Classify` | voxel 分类统计 (d/c/n 计数) | Normal |
| `Phase1_TaskList` | 任务列表生成摘要 | Normal |
| `Phase2_Quadtree` | 四叉树细分深度/采样点数 | Normal |
| `Phase2_QuadtreeDetail` | 每个子域的 AABB/弦高值 | Verbose |
| `Phase3_Cull` | 旧点删除统计 | Normal |
| `Phase4_Merge` | buffer merge 点数/耗时 | Normal |
| `ToolSDF_Eval` | SDF 求值中间结果 | Verbose |
| `Compaction` | 碎片率/规整触发 | Normal |
| `Precision` | 精度监控（Hausdorff采样） | Normal |

**使用模式**：
```cpp
// Normal级别：关键统计
DEBUG_SECTION(Phase0_Classify) {
    DEBUG_INFO_OUT("DELETED=" + std::to_string(nDel) 
                 + " CUT=" + std::to_string(nCut)
                 + " NEW=" + std::to_string(nNew));
}

// Verbose级别：高频细节（每voxel/每点）
DEBUG_SECTION_VERBOSE(Phase2_QuadtreeDetail) {
    DEBUG_INFO_OUT("depth=" + std::to_string(d) + " chordal=" + std::to_string(err));
}
```

### 5.3 禁止事项

- **禁止**在 DEBUG_SECTION 内修改算法状态（纯观察，无副作用）
- **禁止**在 Verbose 标签内做重量级计算（如 Hausdorff 全量计算）——用 Normal 标签+采样代替
- Release 构建不移除 RtDebugSys（保留运行时诊断能力），但默认 `Activate(0)` 关闭

## 7. 开发迭代策略

遵循敏捷迭代原则：
1. **先通后优** — 先实现功能正确的版本（可低性能），后续迭代优化
2. **Phase依赖序** — Phase 0 → 1 → 2 → 3 → 4 顺序实现，每个Phase独立可测
3. **双平台验证** — 关键节点需在 macOS 和 Windows 双平台验证编译
